# КАІ · Наукова аналітика

Налаштовуваний українськомовний сайт для відображення наукової діяльності закладу вищої освіти. Структура інформації побудована за наданим зразком сторінки «Наука — ЛНТУ»; дизайн та реалізація власні. Завантажений HTML використано лише як довідковий матеріал, сторонні скрипти не виконувалися.

## Запуск

Потрібен **Node.js 22 або новіший**. Сервер працює без збірки. Для XLSX використовується ExcelJS 4.4.0 (MIT), його браузерна версія включена локально в src/vendor. Для розробки та тестів установіть залежності за lockfile:

```bash
cd /workspace/kaidata
npm ci --ignore-scripts
npm run vendor
npm start
```

Сервер слухає порт `3000` на всіх інтерфейсах. Можна змінити через `PORT=8080 npm start`; `HOST=127.0.0.1` обмежує прослуховування локальним інтерфейсом. В іншому середовищі виконуйте команду з кореня репозиторію. Для перевірки: `npm test`.

Для статичного хостингу достатньо опублікувати `index.html`, `styles.css`, `src/`, `data/` у корені домену або в підкаталозі (наприклад, GitHub Pages `/kaidata/`). Шляхи до стилів, коду та даних відносні. Node-сервер потрібен лише для локальної розробки. Завантаження через `file://` не підтримується: браузер має отримувати JSON через HTTP. Прямі посилання на розділи використовують `#publications`, `#projects`, `#patents`, `#funding`.

## Перегляд сайту через GitHub Pages

Для репозиторію `romashekpng/kaidata`:

1. Відкрийте **Settings → Pages**.
2. У розділі **Build and deployment** виберіть **Source: Deploy from a branch**.
3. Виберіть гілку **main**, папку **/ (root)** і натисніть **Save**.
4. Дочекайтеся успішного розгортання Pages. Після цього сайт доступний за адресою **https://romashekpng.github.io/kaidata/**.

Кореневий файл `.nojekyll` дозволяє публікувати статичні файли без обробки Jekyll. Node.js і встановлення залежностей на GitHub Pages не потрібні: бібліотека XLSX уже збережена в `src/vendor`. У вкладці **Actions** можна перевірити стан розгортання.

Імпорт у браузері змінює дані лише для цього браузера. Щоб оновити дані для всіх відвідувачів, замініть `data/demo.json` перевіреним JSON-набором у репозиторії та створіть коміт. GitHub Pages опублікує нову версію автоматично. До заміни даних сайт показує демонстраційний набір.

## Можливості

- Огляд із показниками, динамікою, квартилями та розподілом за факультетами.
- Каталог публікацій: рік, пошук за назвою й автором, факультет, квартиль, індексація, сторінки по 10 записів.
- Проєкти: програми, надходження за роками, міжнародні проєкти, роль координатора, фільтр «Активні сьогодні».
- Патенти: пошук за назвою, номером або винахідником, факультет, дата реєстрації.
- Фінансування: динаміка, джерела, порівняльна таблиця. Відсутні дані відрізняються від нульових сум.
- Налаштування назви, сайту, підзаголовка, джерела, кольору та видимості кожного блоку.
- Імпорт JSON, CSV або XLSX із перевіркою, попереднім переглядом і явним застосуванням.
- Вибір формату експорту: CSV, XLSX або JSON. XLSX підтримує весь набір із налаштуваннями; окремі таблиці експортуються у CSV/XLSX. Для публікацій, патентів і проєктів можна застосувати поточний рік та фільтри.
- Приклади JSON, CSV та XLSX завантажуються з розділу «Керування даними».
- Адаптивний інтерфейс, клавіатурна навігація, текстові позначення графіків.

**Початкові дані повністю демонстраційні.** Числа, записи, імена авторів, назви факультетів та кафедр умовні й не є звітністю КАІ. Умовні патенти мають номери `ДЕМО-…`. Значення не перенесено з ЛНТУ і не приписано КАІ як офіційні.

## Теми оформлення

За замовчуванням сайт відкривається із **синьою темою**. Якщо в браузері вже збережено вибір теми, використовується він. На верхній панелі в списку **Тема** можна обрати:

- **Стандартна** — світла тема з прохолодними відтінками.
- **Темна** — темні панелі, світлий текст та контрастні елементи керування.
- **Тепла** — кремовий фон і теплі нейтральні відтінки.
- **Синя** — темно-синє меню та сині акценти з зеленими, червоними й фіолетовими індикаторами за наданим зразком. Фон сторінки та карток такий самий, як у стандартній темі; макет не змінюється.

Еталон синьої теми: меню `#25395d`, активний пункт `#2c66b2`, основні кнопки `#2f6fbc`, фон `#f5f7f9`. Стандартна тема має меню `#101f2c` і зелені акценти. Локальний HTML-перегляд зберігає вибір теми окремо від опублікованого сайта й початково використовує синю тему. Якщо середовище перегляду прибрало атрибут теми з HTML, стилі також використовують синю тему за замовчуванням.

Ті самі варіанти доступні в **Налаштування → Університет → Тема оформлення** з попереднім виглядом кольорів. Тема застосовується одразу; зберігати форму налаштувань для цього не потрібно. Вибір запам’ятовується в поточному браузері, окремо від даних університету. Імпорт, експорт і відновлення набору даних не змінюють обрану тему. Якщо локальне сховище недоступне, тема діє до закриття сторінки. Чотири теми доступні також у завантажуваному HTML-файлі.

## Як підготувати дані КАІ

1. Завантажте приклад JSON через «Імпорт даних → Завантажити JSON» або візьміть [`data/empty.json`](data/empty.json) — порожню основу без демонстраційних записів.
2. Заповніть налаштування університету і потрібні масиви. Установіть `demo: false` лише після заміни всіх умовних записів власними даними.
3. Імпортуйте JSON. Перевірте підсумки та застосуйте набір.
4. Надалі можна оновлювати окремі таблиці через CSV або XLSX. Оберіть формат та обсяг імпорту **перед** вибором файлу.
5. Експортуйте JSON для резервної копії, передачі іншій людині чи публікації.

**Межа збереження:** імпорт і налаштування записуються в `localStorage` поточного браузера для цього домену. Інші користувачі їх не бачать. Якщо браузер заборонив збереження або вичерпав квоту, інтерфейс повідомить про тимчасовий режим; експортуйте JSON. Файли не відправляються на сервер.

**Для спільного публічного сайту:** замініть `data/demo.json` на перевірений експорт із `demo: false` і повторно опублікуйте статичні файли. У браузері, де вже є локальна копія, натисніть «Керування даними → Відновити початковий набір», щоб завантажити серверні дані. Спочатку експортуйте локальні зміни. Назва файлу `demo.json` технічна: позначкою демонстрації керує поле `demo`, а не ім’я файлу.

Спільного редагування на сервері, облікових записів та автоматичної синхронізації зі Scopus/репозиторієм у цій версії немає. Excel підтримується безпосередньо через XLSX або CSV UTF-8. Усі опубліковані файли даних доступні відвідувачам сайту.

## Формат JSON, версія 1

Верхній рівень:

| Поле | Формат |
| --- | --- |
| `schemaVersion` | Число `1` |
| `demo` | `true` для демонстрації, `false` для власного набору |
| `updatedAt` | Дата оновлення `YYYY-MM-DD` |
| `institution` | Налаштування університету |
| `publications` | Масив публікацій, може бути `[]` |
| `projects` | Масив проєктів, може бути `[]` |
| `patents` | Масив патентів, може бути `[]` |
| `revenues` | Масив надходжень, може бути `[]` |

`institution`: `name` (до 180 символів), `shortName` (до 24), `subtitle`, `website` (http/https або порожньо), `accent` (`#RRGGBB`), `sourceNote`, `blocks` (унікальні значення `publications`, `projects`, `patents`, `funding`). Порядок `blocks` визначає порядок пунктів навігації. Вимкнення блоку не видаляє записи. Використовуйте контрастний колір акценту.

### Публікації

```json
{
  "id": "pub-2026-001",
  "title": "Назва наукової публікації",
  "authors": "Автор І. П.; Співавтор А. Б.",
  "year": 2026,
  "faculty": "Назва факультету",
  "department": "Назва кафедри",
  "indexes": ["Scopus", "WoS"],
  "quartile": "Q1",
  "type": "Наукова стаття",
  "url": ""
}
```

`indexes`: `[]`, `["Scopus"]`, `["WoS"]` або `["Scopus", "WoS"]`. `quartile`: `Q1`–`Q4` або `null`. Квартиль дозволено лише для індексованої публікації. Використовуйте квартиль видання на рік публікації. У кожного запису один основний факультет і кафедра.

### Проєкти

```json
{
  "id": "project-001",
  "title": "Назва проєкту",
  "program": "Horizon Europe",
  "startDate": "2025-01-01",
  "endDate": "2027-12-31",
  "role": "Партнер",
  "international": true,
  "faculty": "Назва факультету",
  "funding": [{"year": 2026, "amountUAH": 1200000}],
  "url": ""
}
```

`role`: `Партнер` або `Координатор`. `faculty` можна залишити порожнім. `funding` — **фактичні річні надходження університету** у гривнях, а не весь бюджет консорціуму. Рік не повторюється, має бути в межах виконання проєкту. Роки без надходжень можна пропустити. Іноземну валюту необхідно конвертувати до імпорту.

### Патенти

```json
{
  "id": "patent-001",
  "title": "Назва винаходу",
  "number": "Номер патенту",
  "date": "2026-06-15",
  "authors": "Винахідник І. П.",
  "faculty": "Назва факультету",
  "url": ""
}
```

Один запис — один патент із одним основним факультетом. Не дублюйте патент для кожного співавтора. `number` є текстом і зберігає префікси та початкові нулі.

### Надходження

```json
{"year": 2026, "source": "Послуги наукових лабораторій", "amountUAH": 250000}
```

Записи за тим самим джерелом і роком підсумовуються. Немає запису — немає даних; `amountUAH: 0` — явний нуль. Грантові надходження та ці суми не додаються автоматично: джерела можуть перетинатися.

### Загальні обмеження

Усі `id` — непорожні унікальні рядки в межах відповідного масиву. Роки — цілі 1900–2200. Суми — скінченні невід’ємні числа до 10¹⁵ грн. Дати перевіряються календарно. Посилання — лише http/https без вбудованих облікових даних. Імпорт — до 5 МБ, до 25 000 записів на масив. Структурна перевірка не встановлює достовірність джерел і не дедуплікує записи з різними `id`.

## CSV

UTF-8 із BOM або без, роздільник `;`, `,` або табуляція. Підтримуються лапки, подвійні лапки всередині полів і багаторядковий текст. **Усі наведені колонки обов’язкові**, необов’язкові значення залишайте порожніми. Невідомі та повторювані колонки відхиляються.

| Таблиця | Колонки |
| --- | --- |
| publications | `id,title,authors,year,faculty,department,indexes,quartile,type,url` |
| projects | `id,title,program,startDate,endDate,role,international,faculty,funding,url` |
| patents | `id,title,number,date,authors,faculty,url` |
| revenues | `year,source,amountUAH` |

У CSV `indexes` записується як `Scopus|WoS`, `quartile` без значення — порожня клітинка, `international` — `true`/`false`. `funding` — JSON-масив усередині CSV-клітинки; приклад, який можна завантажити з інтерфейсу, вже містить правильне екранування. Для сум дозволена десяткова кома або крапка; за роздільника-коми клітинку з десятковою комою потрібно взяти в лапки. Експорт CSV використовує `;` та BOM для сумісності з Excel.

**Імпорт CSV замінює всю обрану таблицю за всі роки**, не доповнює її. Інші масиви, налаштування та `demo` зберігаються. Для першого переходу з демонстрації на справжні дані використайте повний JSON, щоб уникнути змішування. Для очищення таблиці імпортуйте JSON із порожнім масивом. Експорт публікацій і патентів включає всі сторінки поточних результатів фільтрації, а не лише видиму сторінку.

У текстових CSV-полях, що починаються із символу формули, експорт додає апостроф для безпечного відкриття в електронних таблицях. Для точного перенесення довільного тексту використовуйте JSON.

## XLSX · Excel

1. Натисніть **Експорт даних**, оберіть XLSX або CSV та обсяг експорту. JSON також залишається доступним.
2. **Повний XLSX** містить 5 аркушів: `Університет`, `Публікації`, `Проєкти`, `Патенти`, `Надходження`. Це формат для повного перенесення разом із налаштуваннями й позначкою демонстрації.
3. У **Керування даними → Імпорт** оберіть XLSX та повний набір або одну таблицю. Для однієї таблиці використовується відповідний аркуш, а якщо в книзі лише один аркуш — його назва може бути довільною. Також розпізнаються технічні назви `settings`, `publications`, `projects`, `patents`, `revenues`.
4. Для CSV потрібна одна таблиця: цей формат не зберігає налаштування університету. Доступний експорт проєктів, включно з полем funding.
5. Перед застосуванням імпорту показуються кількості записів і попередження про заміну. Для XLSX із самими заголовками дозволено очистити обрану таблицю; це явно видно як нуль записів у попередньому перегляді. CSV із самими заголовками не приймається.

Аркуш `Університет` має колонки `key`, `value`: `schemaVersion`, `demo`, `updatedAt`, `institution.name`, `institution.shortName`, `institution.subtitle`, `institution.website`, `institution.accent`, `institution.sourceNote`, `institution.blocks`. Блоки перелічуються через `|`, наприклад `publications|projects|patents|funding`. У повній книзі всі 10 ключів обов’язкові; `demo` — true/false.

Назви колонок таблиць і правила полів такі самі, як для CSV. Числа та логічні значення експортуються власними типами Excel, номери патентів — текстом для збереження початкових нулів. Дати можна вводити як текст YYYY-MM-DD або клітинку дати Excel. `indexes` — `Scopus|WoS`, `funding` — текстовий JSON-масив. Порожній квартиль дозволений.

Використовуйте `.xlsx`, не `.xls`, `.xlsm` або книгу із паролем. Формули, помилки Excel та складні клітинки не приймаються — попередньо вставте звичайні значення. Текст, що починається з `=`, у XLSX залишається текстом і не перетворюється на формулу. Ліміт файлу — 5 МБ, розпакованого вмісту — 50 МБ; до 25 000 записів на таблицю.

### Завантажувана версія без інтернету

`npm run preview:build` створює `/workspace/artifacts/index.html` з вбудованими даними, сторінками, стилями, кодом і бібліотекою XLSX. Це єдиний актуальний файл для вбудованого перегляду в чаті. Кореневий `/workspace/kaidata/index.html` призначений для HTTP-хостингу: для нього потрібні сусідні `src/`, `data/` і `styles.css`; окремий знімок цього файла не завантажить дані. Для іншого місця: `npm run preview:build -- /шлях/сайт.html`. Самодостатня версія підтримує ті самі CSV/XLSX-операції без завантаження додаткових файлів. Після зміни коду або початкового набору її потрібно згенерувати заново і надати користувачеві оновлений результат. Уже відкриті знімки в чаті можуть залишатися попередньої версії.

Браузерна бібліотека та MIT-ліцензія зберігаються в `src/vendor/`; команда `npm run vendor` відновлює їх із пакета, зафіксованого lockfile. Змінюйте версію лише через package.json/lockfile, потім повторюйте перевірки і збірку завантажуваної версії.

## Методологія

- Загальна кількість публікацій — за `year`; Scopus / WoS — об’єднання, а не сума двох баз.
- Q1–Q2 — частка від усіх індексованих записів, включно із записами без квартиля в знаменнику.
- Розподіл за факультетами — за основним факультетом у записі, без повторного обліку співавторів.
- Проєкти — усі, чиї роки початку та завершення включають звітний рік, незалежно від наявності фінансування. «Активні сьогодні» додатково перевіряє поточну дату та належність звітному року.
- Міжнародна частка — частка грантових надходжень проєктів з `international: true`.
- Патенти — за роком дати реєстрації.
- Відсоток зміни — від попереднього календарного року. За нульової або відсутньої бази відсоток не визначається. Поточний рік може бути неповним.

## Адмінка та редактор сторінок

Відкрийте пункт **Адмінка** в лівому меню або маршрут **#admin**. У GitHub Pages це `https://romashekpng.github.io/kaidata/#admin`.

### Створення й редагування

1. Натисніть **Нова сторінка**, задайте назву в меню, заголовок, опис і адресу латиницею (`#page/ваша-адреса`).
2. Додавайте блоки з палітри: **Текст**, **Таблиця**, **Список**, **Банер**, **Картки показників**, **Аналітичний блок**.
3. Редагуйте поля без написання HTML. У таблицях можна змінювати клітинки, додавати й видаляти рядки та колонки. У списках кожен пункт вводиться з нового рядка, нумерація вмикається окремо. Банери мають колір, текст і необов’язкову кнопку.
4. Стрілки змінюють порядок блоків. Блок можна приховати, дублювати або видалити. Кнопка скасування повертає останню структурну зміну (до 20 кроків).
5. **Вигляд сторінки** постійно відкритий поруч із редактором і автоматично показує графіки, діаграми, списки, таблиці та банери. Він оновлюється під час введення тексту, зміни клітинок, додавання, переміщення чи приховування блоків та імпорту даних. Кнопка попереднього перегляду більше не потрібна. На вузьких екранах візуалізація розташована над редактором; на телефоні вона залишається видимою під час прокручування. Область вигляду прокручується окремо й показує чернетку без інтерактивних елементів. **Зберегти сторінку** застосовує зміни до локального сайта. Чернетка не публікується автоматично. Перед виходом браузер попереджає про незбережені зміни.

Наявні 5 сторінок також доступні в редакторі. Початкові графіки й каталоги збережені в блоці **Наявна сторінка аналітики**, тому звичні фільтри продовжують працювати. Додавайте власні блоки до або після нього, приховуйте чи видаляйте його. Для нових сторінок використовуйте окремі аналітичні блоки: показники, динаміка публікацій, квартилі, факультети, проєкти, публікації, патенти та надходження. Вони використовують дані сайта й вибраний рік. Для таких сторінок увімкніть **Показувати фільтр року**. Огляд показників враховує ввімкнені розділи університету.

Порядок сторінок у меню змінюється стрілками в списку сторінок. Вбудовані маршрути не перейменовуються, але їхні назви, заголовки, видимість і блоки редагуються. Власні сторінки можна видаляти, копіювати або переносити через JSON. Відновлення резервної копії охоплює всі сторінки та аналітичні дані.

### Імпорт та експорт блоків

На кожному блоці є **Імпорт** і **Експорт**. На публічних сторінках доступний експорт; редагування виконується через адмінку.

| Тип | JSON | CSV / XLSX |
| --- | --- | --- |
| Текст | Увесь блок | `title,text`, один рядок |
| Банер | Увесь блок | `title,text,tone,linkLabel,linkUrl`, один рядок |
| Список | Увесь блок | `item`, по одному пункту на рядок |
| Таблиця | Заголовок, примітка, колонки та рядки | Довільні унікальні заголовки колонок та рядки |
| Картки показників | Увесь блок | `label,value,unit,note`, по одній картці на рядок |
| Аналітика та початкова сторінка | Налаштування блоку | Кнопки **Імпорт/експорт даних аналітики** відкривають наявний обмін таблицями сайта |

JSON блоку має вигляд `{ "blockVersion": 1, "block": { ... } }`. CSV/XLSX змінює дані поточного блоку, зберігаючи його заголовок/видимість та інші налаштування, крім полів, які явно входять у таблицю (наприклад, title банера). Порожня таблиця, список або набір карток із самими заголовками підтримуються в обох форматах; перед застосуванням видно нуль записів. Для первинних таблиць аналітики діють окремі правила з розділу CSV вище.

XLSX блоку містить **один аркуш**. Формули не виконуються й відхиляються; з Excel вставляйте звичайні значення. Імпорт показує результат перевірки та перші 5 рядків таблиці. Лише **Застосувати імпорт** замінює блок у чернетці; потім збережіть сторінку. Тексти виводяться як текст, а посилання банерів допускають http/https або внутрішній маршрут. JavaScript/HTML у полях не виконується.

### Резервні копії та публікація

- **Експорт сторінки · JSON**: `{ "pageVersion": 1, "page": { ... } }`. Імпорт додає нову копію з унікальною адресою й ідентифікаторами. Копію вбудованої сторінки можна перенести як власну з окремим аналітичним блоком.
- **Резервна копія сайта · JSON**: `{ "packageVersion": 1, "site": { ... }, "data": { ... } }`. Перед експортом збережіть сторінку. Відновлення замінює всі локальні сторінки й аналітичний набір після явного підтвердження попереднього перегляду.
- **Сайт для публікації**: завантажує ZIP із кодом, стилями, локальною бібліотекою XLSX та її ліцензією, поточними `data/pages.json` і `data/demo.json`. Розпакуйте архів, замініть однойменні файли в `romashekpng/kaidata` та створіть коміт. GitHub Pages розгорне ці сторінки для всіх. Так само можна розмістити файли на іншому статичному хостингу.

**Архітектурна межа:** це локальна адмінка для статичного сайта без серверного входу/пароля, а не спільна система з обліковими записами. Інший відвідувач може створити власну локальну копію, але редактор не має доступу на запис у GitHub або на сервер. Приховування сторінки/блоку керує відображенням і не захищає опублікований JSON від читання. Для приватної авторизованої адмінки та автоматичної серверної публікації потрібні окремі сервер, база й автентифікація.

Після оновлення сервера браузер із локальними змінами продовжує їх показувати. Збережіть резервну копію й імпортуйте актуальний JSON сайта або приберіть локальні дані цього сайта, щоб отримати серверну версію. Налаштування теми зберігається окремо. Якщо браузер не зміг записати локальну копію через квоту чи заборону сховища, адмінка явно повідомляє про тимчасовий режим — експортуйте резервну копію до закриття.

Ліміти: 50 сторінок (включно з п’ятьма системними), 50 блоків на сторінку, 12 колонок / 1000 рядків у таблиці, 1000 пунктів у списку, 12 карток у блоці. Вміст сторінок — до 5 МБ; файл блоку/сторінки — до 5 МБ, резервна копія сайта — до 20 МБ. ZIP експортує всі потрібні статичні файли; автоматичного завантаження архіву на GitHub немає. Завантажуваний HTML також містить адмінку й підтримує підготовку ZIP без інтернету.

Файли CMS: `data/pages.json` (версія siteVersion: 1), `src/cms-data.js` (схема й перевірки), `src/cms.js` (редактор і відображення), `src/cms-io.js` (обмін файлами), `src/zip.js` (архів для публікації). Аналітичні JSON/XLSX-експорти з початкового меню залишаються сумісними; для перенесення сторінок користуйтеся резервною копією з адмінки.

## Архітектура й перевірки

`src/spreadsheet.js` — імпорт/експорт XLSX; `src/data.js` — спільний валідатор, CSV-парсер і розрахунки; `src/app.js` — інтерфейс та локальне збереження; `src/icons.js` — локальні SVG-іконки; `styles.css` — адаптивний дизайн. Сторонніх CDN, шрифтів і аналітичних скриптів немає. Довільний HTML із даних екранується; файли не виконуються як код. Сервер обмежує доступ публічними шляхами та встановлює CSP.

`npm test` запускає 43 тести розрахунків, валідації та імпорту/експорту, включно з подвійною індексацією, багаторічними проєктами, відсутніми фінансовими даними, CSV із лапками, відхиленням неправильних URL і захистом CSV від формул. У Chromium додатково перевірено навігацію, фільтри, JSON/CSV-імпорт, збереження після перезавантаження, налаштування блоків, експорт, відновлення та мобільний вигляд. Додатково XLSX перевірено на повному та порожньому наборах, окремих таблицях, числових клітинках, датах Excel, неправильних заголовках, формулах і пошкоджених архівах.
