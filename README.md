# КАІ · Наукова аналітика

Налаштовуваний українськомовний сайт для відображення наукової діяльності закладу вищої освіти. Структура інформації побудована за наданим зразком сторінки «Наука — ЛНТУ»; дизайн та реалізація власні. Завантажений HTML використано лише як довідковий матеріал, сторонні скрипти не виконувалися.

## Запуск

Потрібен **Node.js 22 або новіший**. Сервер працює без збірки. Для XLSX використовується ExcelJS 4.4.0 (MIT), його браузерна версія включена локально в src/vendor. Для розробки та тестів установіть залежності за lockfile:

```bash
cd /workspace/kaidata
npm ci --ignore-scripts
npm run vendor
npm start
```

Сервер слухає порт `3000` на всіх інтерфейсах. Можна змінити через `PORT=8080 npm start`; `HOST=127.0.0.1` обмежує прослуховування локальним інтерфейсом. В іншому середовищі виконуйте команду з кореня репозиторію. Для перевірки: `npm test`.

Для статичного хостингу достатньо опублікувати `index.html`, `styles.css`, `src/`, `data/` у корені домену або в підкаталозі (наприклад, GitHub Pages `/kaidata/`). Шляхи до стилів, коду та даних відносні. Node-сервер потрібен лише для локальної розробки. Завантаження через `file://` не підтримується: браузер має отримувати JSON через HTTP. Прямі посилання на розділи використовують `#publications`, `#projects`, `#patents`, `#funding`.

## Перегляд сайту через GitHub Pages

Для репозиторію `romashekpng/kaidata`:

1. Відкрийте **Settings → Pages**.
2. У розділі **Build and deployment** виберіть **Source: Deploy from a branch**.
3. Виберіть гілку **main**, папку **/ (root)** і натисніть **Save**.
4. Дочекайтеся успішного розгортання Pages. Після цього сайт доступний за адресою **https://romashekpng.github.io/kaidata/**.

Кореневий файл `.nojekyll` дозволяє публікувати статичні файли без обробки Jekyll. Node.js і встановлення залежностей на GitHub Pages не потрібні: бібліотеки XLSX та діаграм уже збережені в `src/vendor`. У вкладці **Actions** можна перевірити стан розгортання.

Імпорт у браузері змінює дані лише для цього браузера. Щоб оновити дані для всіх відвідувачів, замініть `data/demo.json` перевіреним JSON-набором у репозиторії та створіть коміт. GitHub Pages опублікує нову версію автоматично. До заміни даних сайт показує демонстраційний набір.

## Можливості

- Огляд із показниками, динамікою, квартилями та розподілом за факультетами.
- Каталог публікацій: рік, пошук за назвою й автором, факультет, квартиль, індексація, сторінки по 10 записів.
- Проєкти: програми, надходження за роками, міжнародні проєкти, роль координатора, фільтр «Активні сьогодні».
- Патенти: пошук за назвою, номером або винахідником, факультет, дата реєстрації.
- Фінансування: динаміка, джерела, порівняльна таблиця. Відсутні дані відрізняються від нульових сум.
- Налаштування назви, сайту, підзаголовка, джерела, кольору та видимості кожного блоку.
- Імпорт JSON, CSV або XLSX із перевіркою, попереднім переглядом і явним застосуванням.
- Вибір формату експорту: CSV, XLSX або JSON. XLSX підтримує весь набір із налаштуваннями; окремі таблиці експортуються у CSV/XLSX. Для публікацій, патентів і проєктів можна застосувати поточний рік та фільтри.
- Приклади JSON, CSV та XLSX завантажуються з розділу «Керування даними».
- Адаптивний інтерфейс, клавіатурна навігація, текстові позначення графіків.

**Початкові дані повністю демонстраційні.** Числа, записи, імена авторів, назви факультетів та кафедр умовні й не є звітністю КАІ. Умовні патенти мають номери `ДЕМО-…`. Значення не перенесено з ЛНТУ і не приписано КАІ як офіційні.

## Теми оформлення

За замовчуванням сайт відкривається із **синьою темою**. Якщо в браузері вже збережено вибір теми, використовується він. На верхній панелі в списку **Тема** можна обрати:

- **Стандартна** — світла тема з прохолодними відтінками.
- **Темна** — темні панелі, світлий текст та контрастні елементи керування.
- **Тепла** — кремовий фон і теплі нейтральні відтінки.
- **Синя** — темно-синє меню та сині акценти з зеленими, червоними й фіолетовими індикаторами за наданим зразком. Фон сторінки та карток такий самий, як у стандартній темі; макет не змінюється.

Еталон синьої теми: меню `#25395d`, активний пункт `#2c66b2`, основні кнопки `#2f6fbc`, фон `#f5f7f9`. Стандартна тема має меню `#101f2c` і зелені акценти. Локальний HTML-перегляд зберігає вибір теми окремо від опублікованого сайта й початково використовує синю тему. Якщо середовище перегляду прибрало атрибут теми з HTML, стилі також використовують синю тему за замовчуванням.

Ті самі варіанти доступні в **Налаштування → Університет → Тема оформлення** з попереднім виглядом кольорів. Тема застосовується одразу; зберігати форму налаштувань для цього не потрібно. Вибір запам’ятовується в поточному браузері, окремо від даних університету. Імпорт, експорт і відновлення набору даних не змінюють обрану тему. Якщо локальне сховище недоступне, тема діє до закриття сторінки. Чотири теми доступні також у завантажуваному HTML-файлі.

## Як підготувати дані КАІ

1. Завантажте приклад JSON через «Імпорт даних → Завантажити JSON» або візьміть [`data/empty.json`](data/empty.json) — порожню основу без демонстраційних записів.
2. Заповніть налаштування університету і потрібні масиви. Установіть `demo: false` лише після заміни всіх умовних записів власними даними.
3. Імпортуйте JSON. Перевірте підсумки та застосуйте набір.
4. Надалі можна оновлювати окремі таблиці через CSV або XLSX. Оберіть формат та обсяг імпорту **перед** вибором файлу.
5. Експортуйте JSON для резервної копії, передачі іншій людині чи публікації.

**Межа збереження:** імпорт і налаштування записуються в `localStorage` поточного браузера для цього домену. Інші користувачі їх не бачать. Якщо браузер заборонив збереження або вичерпав квоту, інтерфейс повідомить про тимчасовий режим; експортуйте JSON. Файли не відправляються на сервер.

**Для спільного публічного сайту:** замініть `data/demo.json` на перевірений експорт із `demo: false` і повторно опублікуйте статичні файли. У браузері, де вже є локальна копія, натисніть «Керування даними → Відновити початковий набір», щоб завантажити серверні дані. Спочатку експортуйте локальні зміни. Назва файлу `demo.json` технічна: позначкою демонстрації керує поле `demo`, а не ім’я файлу.

Спільного редагування на сервері, облікових записів та автоматичної синхронізації зі Scopus/репозиторієм у цій версії немає. Excel підтримується безпосередньо через XLSX або CSV UTF-8. Усі опубліковані файли даних доступні відвідувачам сайту.

## Формат JSON, версія 1

Верхній рівень:

| Поле | Формат |
| --- | --- |
| `schemaVersion` | Число `2` (старі набори `1` підтримуються) |
| `demo` | `true` для демонстрації, `false` для власного набору |
| `updatedAt` | Дата оновлення `YYYY-MM-DD` |
| `institution` | Налаштування університету |
| `publications` | Масив публікацій, може бути `[]` |
| `projects` | Масив проєктів, може бути `[]` |
| `patents` | Масив патентів, може бути `[]` |
| `revenues` | Масив надходжень, може бути `[]` |

`institution`: `name` (до 180 символів), `shortName` (до 24), `subtitle`, `website` (http/https або порожньо), `accent` (`#RRGGBB`), `sourceNote`, `blocks` (унікальні значення `publications`, `projects`, `patents`, `funding`). Порядок `blocks` визначає порядок пунктів навігації. Вимкнення блоку не видаляє записи. Використовуйте контрастний колір акценту.

### Публікації

```json
{
  "id": "pub-2026-001",
  "title": "Назва наукової публікації",
  "authors": "Автор І. П.; Співавтор А. Б.",
  "year": 2026,
  "faculty": "Назва факультету",
  "department": "Назва кафедри",
  "indexes": ["Scopus", "WoS"],
  "quartile": "Q1",
  "type": "Наукова стаття",
  "url": ""
}
```

`indexes`: `[]`, `["Scopus"]`, `["WoS"]` або `["Scopus", "WoS"]`. `quartile`: `Q1`–`Q4` або `null`. При імпорті також дозволено «Без квартиля» та порожнє значення; вони нормалізуються до `null`. Значення Q1–Q4 дозволено лише для індексованої публікації. Використовуйте квартиль видання на рік публікації. У кожного запису один основний факультет і кафедра.

### Проєкти

```json
{
  "id": "project-001",
  "title": "Назва проєкту",
  "program": "Horizon Europe",
  "startDate": "2025-01-01",
  "endDate": "2027-12-31",
  "role": "Партнер",
  "international": true,
  "faculty": "Назва факультету",
  "funding": [{"year": 2026, "amountThousandUAH": 1200}],
  "url": ""
}
```

`role`: `Партнер` або `Координатор`. `faculty` можна залишити порожнім. `funding` — **фактичні річні надходження університету** у тис. грн, а не весь бюджет консорціуму. Рік не повторюється, має бути в межах виконання проєкту. Роки без надходжень можна пропустити. Іноземну валюту необхідно конвертувати до імпорту.

### Патенти

```json
{
  "id": "patent-001",
  "title": "Назва винаходу",
  "number": "Номер патенту",
  "date": "2026-06-15",
  "authors": "Винахідник І. П.",
  "faculty": "Назва факультету",
  "url": ""
}
```

Один запис — один патент із одним основним факультетом. Не дублюйте патент для кожного співавтора. `number` є текстом і зберігає префікси та початкові нулі.

### Надходження

```json
{"year": 2026, "source": "Послуги наукових лабораторій", "amountThousandUAH": 250}
```

Записи за тим самим джерелом і роком підсумовуються. Немає запису — немає даних; `amountThousandUAH: 0` — явний нуль. Грантові надходження та ці суми не додаються автоматично: джерела можуть перетинатися.

### Загальні обмеження

Усі `id` — непорожні унікальні рядки в межах відповідного масиву. Роки — цілі 1900–2200. Суми — скінченні невід’ємні числа до 10¹² тис. грн. Дати перевіряються календарно. Посилання — лише http/https без вбудованих облікових даних. Імпорт — до 5 МБ, до 25 000 записів на масив. Структурна перевірка не встановлює достовірність джерел і не дедуплікує записи з різними `id`.

## CSV

UTF-8 із BOM або без, роздільник `;`, `,` або табуляція. Підтримуються лапки, подвійні лапки всередині полів і багаторядковий текст. **Усі наведені колонки обов’язкові**, необов’язкові значення залишайте порожніми. Невідомі та повторювані колонки відхиляються.

| Таблиця | Колонки |
| --- | --- |
| publications | `id,title,authors,year,faculty,department,indexes,quartile,type,url` |
| projects | `id,title,program,startDate,endDate,role,international,faculty,funding,url,progressByYear` |
| patents | `id,title,number,date,authors,faculty,url` |
| revenues | `year,source,amountThousandUAH` |

У CSV `indexes` записується як `Scopus|WoS`, `quartile` без значення — порожня клітинка або «Без квартиля», `international` — `true`/`false`. `funding` — JSON-масив усередині CSV-клітинки; приклад, який можна завантажити з інтерфейсу, вже містить правильне екранування. Для сум дозволена десяткова кома або крапка; за роздільника-коми клітинку з десятковою комою потрібно взяти в лапки. Експорт CSV використовує `;` та BOM для сумісності з Excel.

**Імпорт CSV замінює всю обрану таблицю за всі роки**, не доповнює її. Інші масиви, налаштування та `demo` зберігаються. Для першого переходу з демонстрації на справжні дані використайте повний JSON, щоб уникнути змішування. Для очищення таблиці імпортуйте JSON із порожнім масивом. Експорт публікацій і патентів включає всі сторінки поточних результатів фільтрації, а не лише видиму сторінку.

У текстових CSV-полях, що починаються із символу формули, експорт додає апостроф для безпечного відкриття в електронних таблицях. Для точного перенесення довільного тексту використовуйте JSON.

## XLSX · Excel

1. Натисніть **Експорт даних**, оберіть XLSX або CSV та обсяг експорту. JSON також залишається доступним.
2. **Повний XLSX** містить 5 аркушів: `Університет`, `Публікації`, `Проєкти`, `Патенти`, `Надходження`. Це формат для повного перенесення разом із налаштуваннями й позначкою демонстрації.
3. У **Керування даними → Імпорт** оберіть XLSX та повний набір або одну таблицю. Для однієї таблиці використовується відповідний аркуш, а якщо в книзі лише один аркуш — його назва може бути довільною. Також розпізнаються технічні назви `settings`, `publications`, `projects`, `patents`, `revenues`.
4. Для CSV потрібна одна таблиця: цей формат не зберігає налаштування університету. Доступний експорт проєктів, включно з полем funding.
5. Перед застосуванням імпорту показуються кількості записів і попередження про заміну. Для XLSX із самими заголовками дозволено очистити обрану таблицю; це явно видно як нуль записів у попередньому перегляді. CSV із самими заголовками не приймається.

Аркуш `Університет` має колонки `key`, `value`: `schemaVersion`, `demo`, `updatedAt`, `institution.name`, `institution.shortName`, `institution.subtitle`, `institution.website`, `institution.accent`, `institution.sourceNote`, `institution.blocks`. Блоки перелічуються через `|`, наприклад `publications|projects|patents|funding`. У повній книзі всі 10 ключів обов’язкові; `demo` — true/false.

Назви колонок таблиць і правила полів такі самі, як для CSV. Числа та логічні значення експортуються власними типами Excel, номери патентів — текстом для збереження початкових нулів. Дати можна вводити як текст YYYY-MM-DD або клітинку дати Excel. `indexes` — `Scopus|WoS`, `funding` і необов’язкове `progressByYear` — текстові JSON-масиви. Порожній квартиль дозволений.

Використовуйте `.xlsx`, не `.xls`, `.xlsm` або книгу із паролем. Формули, помилки Excel та складні клітинки не приймаються — попередньо вставте звичайні значення. Текст, що починається з `=`, у XLSX залишається текстом і не перетворюється на формулу. Ліміт файлу — 5 МБ, розпакованого вмісту — 50 МБ; до 25 000 записів на таблицю.

### Завантажувана версія без інтернету

`npm run preview:build` створює `/workspace/artifacts/index.html` з вбудованими даними, сторінками, стилями, кодом, бібліотекою XLSX і трьома бібліотеками діаграм. Код, дані й локальні бібліотеки упаковано всередині HTML у стисненому вигляді; браузер розпаковує їх без інтернету через DecompressionStream (актуальні Chrome, Edge, Firefox, Safari). Це єдиний актуальний файл для вбудованого перегляду в чаті. Кореневий `/workspace/kaidata/index.html` призначений для HTTP-хостингу: для нього потрібні сусідні `src/`, `data/` і `styles.css`; окремий знімок цього файла не завантажить дані. Для іншого місця: `npm run preview:build -- /шлях/сайт.html`. Самодостатня версія підтримує ті самі CSV/XLSX-операції без завантаження додаткових файлів. Після зміни коду або початкового набору її потрібно згенерувати заново і надати користувачеві оновлений результат. Уже відкриті знімки в чаті можуть залишатися попередньої версії.

Браузерна бібліотека та MIT-ліцензія зберігаються в `src/vendor/`; команда `npm run vendor` відновлює їх із пакета, зафіксованого lockfile. Змінюйте версію лише через package.json/lockfile, потім повторюйте перевірки і збірку завантажуваної версії.

## Методологія

- Загальна кількість публікацій — за `year`; Scopus / WoS — об’єднання, а не сума двох баз.
- Q1–Q2 — частка від усіх індексованих записів, включно із записами без квартиля в знаменнику.
- Розподіл за факультетами — за основним факультетом у записі, без повторного обліку співавторів.
- Проєкти — усі, чиї роки початку та завершення включають звітний рік, незалежно від наявності фінансування. «Активні сьогодні» додатково перевіряє поточну дату та належність звітному року.
- Міжнародна частка — частка грантових надходжень проєктів з `international: true`.
- Патенти — за роком дати реєстрації.
- Відсоток зміни — від попереднього календарного року. За нульової або відсутньої бази відсоток не визначається. Поточний рік може бути неповним.

## Адмінка та редактор сторінок

Відкрийте пункт **Адмінка** в лівому меню або маршрут **#admin**. У GitHub Pages це `https://romashekpng.github.io/kaidata/#admin`.

### Створення й редагування

1. Натисніть **Нова сторінка**, задайте назву в меню, заголовок, опис і адресу латиницею (`#page/ваша-адреса`).
2. Додавайте блоки з палітри: **Текст**, **Таблиця**, **Список**, **Банер**, **Картки показників**, **Графік / діаграма**, **Аналітичний блок**.
3. Редагуйте поля без написання HTML. У таблицях можна змінювати клітинки, додавати й видаляти рядки та колонки. У списках кожен пункт вводиться з нового рядка, нумерація вмикається окремо. Банери мають колір, текст і необов’язкову кнопку.
4. Стрілки змінюють порядок блоків. Блок можна приховати, дублювати або видалити. Кнопка скасування повертає останню структурну зміну (до 20 кроків).
5. **Вигляд сторінки** розташований на всю ширину над редактором на всіх екранах. Під ним послідовно йдуть **Параметри сторінки**, **Блоки сторінки** та **Додати блок**. Візуалізація використовує ті самі заголовки, кнопки, фільтр року, повідомлення, блоки та правила адаптивного оформлення, що й публічна сторінка. Висота підлаштовується під увесь вміст: перегляд не перекриває редактор і прокручується разом зі сторінкою. Він автоматично оновлюється під час введення тексту, зміни клітинок, додавання, переміщення чи приховування блоків та імпорту даних. Це чернетка: доступні керування блоками, легенди графіків і вибір звітного року. **Зберегти сторінку** застосовує зміни до локального сайта. Чернетка не публікується автоматично. Перед виходом браузер попереджає про незбережені зміни.

Наявні 5 сторінок також доступні в редакторі. Старі складені блоки «Наявна сторінка аналітики» автоматично розділяються на окремі графіки, групи карток, каталоги та інші блоки. Порядок доданих користувачем блоків зберігається. Перетворення підтримує старі резервні копії й виконується один раз для кожного складеного блоку; зміни записуються локально після збереження сторінки. Налаштування ввімкнених розділів університету продовжує керувати відповідними аналітичними блоками.

Порядок сторінок у меню змінюється стрілками в списку сторінок. Вбудовані маршрути не перейменовуються, але їхні назви, заголовки, видимість і блоки редагуються. Власні сторінки можна видаляти, копіювати або переносити через JSON. Відновлення резервної копії охоплює всі сторінки та аналітичні дані.

### Кнопки безпосередньо на блоках

У «Вигляд сторінки» кожний видимий блок має панель у верхньому правому куті: **Налаштування**, **Редагувати**, **Експорт**, **Імпорт**, **Ширина**. Ці самі дії доступні в редакторі нижче. На публічній сторінці кнопки редагування не показуються.

- **Налаштування графіка:** стекові / груповані стовпчики, горизонтальна стовпчаста діаграма, лінійчата діаграма прогресу, лінійний графік, кільцева / кругова діаграма; готові палітри та власні кольори; легенда вгорі, внизу, праворуч або прихована; загальні суми, підсумок «Разом» у підказці, значення сегментів, висота та звіт за весь період. Натискання на елементи легенди приховує серії; підсумки враховують лише активні серії.
- **Лінійчата діаграма прогресу:** підпис і значення розміщені над тонкою горизонтальною смугою. Довжина відносна до найбільшого значення. Пункт **Нумерація** вмикає / вимикає номери на початку рядків. «Внесок факультетів» використовує цей тип початково; старі збережені стандартні стовпчики цього блоку оновлюються зі збереженням даних і ширини.
- **Горизонтальна стовпчаста діаграма:** серії складаються по горизонталі, налаштування **Виводити загальну суму справа від стовпчиків** показує підсумки праворуч. **Переносити довгі назви** початково вимкнено; після ввімкнення назви переносяться відповідно до ширини блоку, а висота рядків підлаштовується під текст. Палітри, легенда, значення сегментів, підказки та період налаштовуються так само, як у стекових стовпчиків.
- **Дані графіка:** пункт **Відображати Дані графіка** початково вимкнено. Увімкнення додає під графіком розкривний розділ із таблицею; експорт доступний незалежно від нього.
- **Кільцева та кругова діаграми:** **Відображати числові значення всередині сегментів у відсотках** працює незалежно від числових підписів. Можна показувати тільки відсотки або числа й відсотки разом. Відсотки перераховуються від суми видимих сегментів після перемикання легенди.
- **Період блоку:** у правому верхньому куті заголовка показується звітний рік або діапазон фактично представлених років, наприклад **2026** чи **2021-2026**. Для автоматичних карток це вибраний рік; для багаторічних графіків — їхній період. Порожні майбутні фінансові роки не розширюють діапазон. Для власних даних можна вказати **Рік або діапазон** у налаштуваннях; без нього система визначає період із даних або з контексту створення ручної копії.
- **Картки:** від 1 до 6 карток у рядку; на телефоні — не більше двох.
- **Списки й таблиці:** «Показувати весь список (без прокрутки)» початково вимкнено. Увімкнення прибирає вертикальне обмеження, а в каталозі також показує всі записи без поділу на сторінки. Горизонтальна прокрутка широких таблиць зберігається.
- **Ширина:** 33%, 50%, 66%, 75%, 100% або власне значення від 1 до 100%. Сусідні блоки розміщуються в рядок, якщо поміщаються; на телефоні всі займають повну ширину.
- **Редагувати:** табличний редактор із додаванням / видаленням рядків і колонок, перетягуванням за ⋮⋮ та стрілками для клавіатури. Для графіка перша колонка містить підписи, решта — числа. Порожні клітинки означають відсутність даних. Набір полів тексту, банера, списку й карток фіксований; їхній порядок можна змінювати.
- **Експорт / імпорт:** JSON зберігає повну конфігурацію блоку; CSV та XLSX передають табличні дані. Для графіків та аналітики доступні всі три формати. Імпорт перевіряється перед застосуванням.

Аналітичний блок має два режими: **Аналітика сайта** або **Власні дані цього блоку**. Ручне редагування чи імпорт CSV/XLSX створює окремий набір для блоку, не змінюючи вихідні публікації, проєкти чи патенти. Ручна копія також запам’ятовує свій період у полі `dataPeriod`, щоб зміна звітного року не приписувала їй інший рік. Повернути автоматичний розрахунок можна в налаштуваннях. Для спільної зміни вихідних записів використовуйте «Керування даними». Налаштування періоду фільтрує ручні графіки за роком, якщо перша колонка містить роки.

**Застосувати до чернетки** оновлює візуалізацію. Після цього натисніть **Зберегти сторінку**. Резервна копія JSON і ZIP для публікації містять ширини, оформлення та власні дані блоків. Збереження залишається локальним у браузері; для GitHub потрібно опублікувати файли або передати повну резервну копію для оновлення проєкту.

### Імпорт та експорт блоків

На кожному блоці є **Імпорт** і **Експорт**. На публічних сторінках доступний експорт; редагування виконується через адмінку.

| Тип | JSON | CSV / XLSX |
| --- | --- | --- |
| Текст | Увесь блок | `title,text`, один рядок |
| Банер | Увесь блок | `title,text,tone,linkLabel,linkUrl`, один рядок |
| Список | Увесь блок | `item`, по одному пункту на рядок |
| Таблиця | Заголовок, примітка, колонки та рядки | Довільні унікальні заголовки колонок та рядки |
| Картки показників | Увесь блок | `label,value,unit,note`, по одній картці на рядок |
| Графік / діаграма | Дані та всі налаштування | Перша колонка — підписи, решта — числові серії |
| Аналітичний блок | Джерело, режим, дані та налаштування | Поточні агреговані дані блоку; імпорт переводить його в ручний режим |
| Стара складена сторінка (якщо збережена через ліміт блоків) | Налаштування | Вихідні дані через **Імпорт/експорт даних аналітики** |

JSON блоку має вигляд `{ "blockVersion": 1, "block": { ... } }`. CSV/XLSX змінює дані поточного блоку, зберігаючи його заголовок/видимість та інші налаштування, крім полів, які явно входять у таблицю (наприклад, title банера). Порожня таблиця, список або набір карток із самими заголовками підтримуються в обох форматах; перед застосуванням видно нуль записів. Для первинних таблиць аналітики діють окремі правила з розділу CSV вище.

XLSX блоку містить **один аркуш**. Формули не виконуються й відхиляються; з Excel вставляйте звичайні значення. Імпорт показує результат перевірки та перші 5 рядків таблиці. Лише **Застосувати імпорт** замінює блок у чернетці; потім збережіть сторінку. Тексти виводяться як текст, а посилання банерів допускають http/https або внутрішній маршрут. JavaScript/HTML у полях не виконується.

### Резервні копії та публікація

- **Експорт сторінки · JSON**: `{ "pageVersion": 1, "page": { ... } }`. Імпорт додає нову копію з унікальною адресою й ідентифікаторами. Копію вбудованої сторінки можна перенести як власну з окремим аналітичним блоком.
- **Резервна копія сайта · JSON**: `{ "packageVersion": 1, "site": { ... }, "data": { ... } }`. Перед експортом збережіть сторінку. Відновлення замінює всі локальні сторінки й аналітичний набір після явного підтвердження попереднього перегляду.
- **Сайт для публікації**: відкриває вибір ZIP з адмінкою (`kai-site-with-admin.zip`) або лише для відвідувачів (`kai-site-visitors.zip`). Обидва містять поточні збережені `data/pages.json` і `data/demo.json`; редактор та бібліотека XLSX включаються лише у варіант з адмінкою. Розпакуйте вибраний архів і замініть вміст сайта. При переході на варіант без адмінки також видаліть старі файли, яких немає в новому архіві.

**Архітектурна межа:** це локальна адмінка для статичного сайта без серверного входу/пароля, а не спільна система з обліковими записами. Інший відвідувач може створити власну локальну копію, але редактор не має доступу на запис у GitHub або на сервер. Приховування сторінки/блоку керує відображенням і не захищає опублікований JSON від читання. Для приватної авторизованої адмінки та автоматичної серверної публікації потрібні окремі сервер, база й автентифікація.

Після оновлення сервера браузер із локальними змінами продовжує їх показувати. Збережіть резервну копію й імпортуйте актуальний JSON сайта або приберіть локальні дані цього сайта, щоб отримати серверну версію. Налаштування теми зберігається окремо. Якщо браузер не зміг записати локальну копію через квоту чи заборону сховища, адмінка явно повідомляє про тимчасовий режим — експортуйте резервну копію до закриття.

Ліміти: 50 сторінок (включно з п’ятьма системними), 50 блоків на сторінку, 12 колонок / 1000 рядків у таблиці, 1000 пунктів у списку, 12 карток у блоці. Вміст сторінок — до 5 МБ; файл блоку/сторінки — до 5 МБ, резервна копія сайта — до 20 МБ. ZIP експортує всі потрібні статичні файли; автоматичного завантаження архіву на GitHub немає. Завантажуваний HTML також містить адмінку й підтримує підготовку ZIP без інтернету.

Файли CMS: `data/pages.json` (версія siteVersion: 1), `src/cms-data.js` (схема й перевірки), `src/cms.js` (редактор і відображення), `src/cms-io.js` (обмін файлами), `src/zip.js` (архів для публікації). Аналітичні JSON/XLSX-експорти з початкового меню залишаються сумісними; для перенесення сторінок користуйтеся резервною копією з адмінки.

## Архітектура й перевірки

`src/spreadsheet.js` — імпорт/експорт XLSX; `src/data.js` — спільний валідатор, CSV-парсер і розрахунки; `src/app.js` — інтерфейс та локальне збереження; `src/icons.js` — локальні SVG-іконки; `styles.css` — адаптивний дизайн. Сторонніх CDN, шрифтів і аналітичних скриптів немає. Довільний HTML із даних екранується; файли не виконуються як код. Сервер обмежує доступ публічними шляхами та встановлює CSP.

`npm test` запускає 43 тести розрахунків, валідації та імпорту/експорту, включно з подвійною індексацією, багаторічними проєктами, відсутніми фінансовими даними, CSV із лапками, відхиленням неправильних URL і захистом CSV від формул. У Chromium додатково перевірено навігацію, фільтри, JSON/CSV-імпорт, збереження після перезавантаження, налаштування блоків, експорт, відновлення та мобільний вигляд. Додатково XLSX перевірено на повному та порожньому наборах, окремих таблицях, числових клітинках, датах Excel, неправильних заголовках, формулах і пошкоджених архівах.

Текстові блоки: у «Налаштуваннях» є вибір фону — колір меню, основний акцент і відтінки поточної теми, стандартний фон або власний колір із палітри. Кольори теми автоматично змінюються з темою сайта; власний колір зберігається незалежно від неї. Колір тексту забезпечує контраст із фоном. Налаштування фону зберігаються зі сторінкою та в резервній копії JSON.


### Пресети стилів сайта

Відкрийте **Налаштування → Стилі**. Є чотири початкові пресети: «Стандартний», «Компактний», «Комфортний» і «Компактний 1». Типово застосовується «Компактний 1». Вкладка налаштовує розміри основного тексту, заголовків сторінок і блоків, чисел у картках, меню, кнопок та полів, таблиць і списків, підписів діаграм і приміток. Також доступні міжрядковий інтервал, відступи між абзацами й блоками, внутрішні відступи, висота рядків таблиць через відступи клітинок та заокруглення кутів.

Виберіть пресет для редагування або створіть копію кнопкою **«+ Новий пресет із поточного»**. Його можна перейменувати, змінити, видалити чи повернути початкові значення. До 20 пресетів. Поле **«Пресет за замовчуванням»** визначає вигляд сайта після відкриття. Перегляд під час редагування показує пресет, який редагується; після збереження застосовується типовий. Закриття без збереження скасовує зміни.

**«Зберегти стилі»** зберігає пресети у `institution.styles` поточного набору даних. Адмінка і сторінки для відвідувачів використовують однакові стилі. Конфігурація переноситься в резервній копії `site-backup.json`, повному JSON/XLSX наборі та ZIP **«Сайт для публікації»**. Частковий CSV/XLSX імпорт даних зберігає налаштування стилів. Для наборів без `institution.styles` редактор і сайт відвідувачів застосовують типовий «Компактний 1». Наявні збережені власні пресети та їхній вибір зберігаються. Саме збереження в браузері не змінює файли GitHub: для спільного вигляду опублікуйте ZIP, для перенесення на інший ПК імпортуйте резервну копію.


### Каталог грантових проєктів

У блоці «Грантові проєкти» є пошук за назвою чи програмою, вкладки з програмами наявних записів та фільтр ролі ЗВО («Координатор» / «Партнер»). Фільтри поєднуються; лічильник показує кількість відібраних записів із загальної кількості за звітний рік. Кнопка «Скинути фільтри» повертає повний перелік. Фільтри окремі для кожного блоку й не змінюють вихідні дані або вміст експорту. Вони працюють і в адмінці, і на сторінках для відвідувачів.

Картки містять програму, роль, строки, надходження та смугу часового прогресу. Прогрес обчислюється за датами початку й завершення станом на поточну дату в часовому поясі Europe/Kyiv: до початку — 0%, після завершення — 100%. Це частка минулого строку, а не оцінка виконаних робіт. Для некоректних або відсутніх дат смуга не будується.

У **Налаштуваннях блоку → Картки грантових проєктів** можна незалежно ввімкнути або вимкнути земну кулю для міжнародних проєктів та прапор України для українських. Ознака береться з `international` у вихідних проєктах. Для ручного блоку CSV/XLSX має додаткову колонку **«Міжнародний»**: `true` / `false` (також підтримуються `так` / `ні`, `1` / `0`). Порожнє значення або відсутня колонка означає невідомий тип: позначення не додається. Старі ручні таблиці підтримуються. Дані, ознака міжнародності та налаштування іконок зберігаються в резервних копіях і переносяться через експорт/імпорт блоку.


### Фон окремих карток показників

У **Картки показників → Редагувати** кожен рядок має поле **«Фон картки»**: колір меню, акцент та відтінки поточної теми, стандартний фон або власний колір із палітри. Кольори теми змінюються разом із темою сайта, власний колір залишається незмінним. Колір тексту автоматично забезпечує контраст із фоном.

Фон переміщується разом із рядком при перетягуванні чи використанні стрілок. Натисніть **«Застосувати до чернетки»**, потім **«Зберегти сторінку»**. Для автоматичних аналітичних показників зміна лише фону або порядку карток зберігає автоматичний розрахунок, іконки й усі пояснення. Ручну копію створює лише зміна чисел, назв або приміток; вихідні записи сайта залишаються окремими.

Підтримуються звичайні картки та аналітичні блоки основних показників, фінансування й патентів. Фони зберігаються в JSON резервній копії та при експорті/імпорті CSV/XLSX блоку через додаткові колонки `background` і `backgroundColor`. Старі файли з `label`, `value`, `unit`, `note` також імпортуються зі стандартним фоном. Доступні значення `background`: `default`, `menu`, `accent`, `blue`, `green`, `amber`, `violet`, `custom`; `backgroundColor` — колір у форматі `#RRGGBB`. Дві колонки оформлення не зменшують ліміт 12 колонок даних в аналітичному блоці.


### Збереження іконок і порівнянь після вибору фону

Оформлення автоматичних показників зберігається окремо в `metricAppearance` за ключем картки. Фон і порядок не вимикають оновлення за звітним роком, іконки, індексацію, частки чи порівняння з попереднім роком. Це діє і для редагування, і для імпорту CSV/XLSX з тими самими даними.

Старі ручні знімки, створені помилково після зміни фону, відновлюються в автоматичний режим у пам’яті, якщо їхні числа й тексти збігаються з даними сайта за збережений рік. Вибрані кольори й порядок зберігаються; сховище браузера без збереження сторінки не перезаписується. Власноруч змінені значення автоматично не підміняються. Для них у **Налаштуваннях блоку** є кнопка **«Відновити автоматичні картки зі збереженням кольорів»**. Після застосування та збереження можна повернути попередні ручні значення, вибравши джерело **«Власні дані цього блоку»**: їхня копія зберігається в `metricManualBackup` та повній резервній копії JSON.

У ручному режимі відомі показники зберігають свої іконки. Автоматичні пояснення та порівняння використовуються лише для рядків, дані яких відповідають вихідним показникам за звітний рік; власні числа й примітки відображаються як внесені користувачем.

Для легенди графіка при розташуванні **«Вгорі»** або **«Внизу»** праворуч доступний чекбокс **«Вирівняти по центру»**. Початково вимкнений. Увімкнення центрує також перенесені рядки легенди. Для **«Праворуч»** і **«Приховати»** чекбокс не показується, а параметр не впливає на відображення. Вибір зберігається з блоком у резервних копіях та експорті/імпорті.


### Два варіанти сайта для публікації

В адмінці натисніть **«Сайт для публікації»** та виберіть варіант, потім **«Завантажити ZIP»**:

- **Зберегти сайт з адмінкою** — `kai-site-with-admin.zip`. Містить редактор сторінок і блоків, імпорт даних, налаштування, резервні копії та повторний експорт обох варіантів. Початково вибрано цей варіант. Редагування, як і раніше, зберігається в поточному браузері.
- **Зберегти сайт без адмінки** — `kai-site-visitors.zip`. Окремий файл запуску `src/viewer.js` і лише модулі відображення. Редактор `src/cms.js`, вхідний файл з редактором `src/app.js`, імпорт/експорт `src/cms-io.js`, модуль XLSX, бібліотека ExcelJS і генератор архівів не включаються. Залишаються сторінки, вибір звітного року та теми відображення, пошук, фільтри, легенди й графіки. Перехід на `#admin` повертає на доступну сторінку перегляду.

Обидва архіви містять поточні збережені дані, сторінки, типографічні пресети, кольори та оформлення карток. Незбережену чернетку потрібно спочатку зберегти. Версія для відвідувачів не читає старі локальні редагування даних або сторінок із браузера: використовуються файли опублікованого архіву. Вона також не містить ручних резервних даних `metricManualBackup`, прихованих блоків або прихованих користувацьких сторінок.

Для подальших оновлень зберігайте версію **з адмінкою** або повну резервну копію `site-backup.json`. Внесіть зміни в ній і підготуйте новий ZIP для відвідувачів. Заміна варіанта на вже опублікованому сайті потребує видалення старих файлів, відсутніх у новому архіві, а не лише завантаження файлів поверх старих. Інструкції є також у `PUBLICATION.txt` кожного ZIP. Поточний самодостатній перегляд у чаті залишається версією з адмінкою та вміє підготувати обидва ZIP без мережевих запитів.

`src/analytics.js` і `src/site-view.js` спільні для редактора та версії відвідувачів, щоб обидва варіанти зберігали ті самі показники, іконки, порівняння й поведінку графіків. `src/publication.js` визначає склад кожного архіву.


### Бібліотеки діаграм

У **Налаштуваннях** кожної діаграми можна вибрати активну бібліотеку: **Apache ECharts 6.0.0**, **Chart.js 4.5.1** або **Plotly.js 3.3.1**. Нижній перемикач «Редагувати параметри для» дозволяє підготувати параметри іншої бібліотеки без її активації. Тип діаграми, палітра, легенда, підсумки, підписи, період фільтрації та висота зберігаються в окремому профілі кожної бібліотеки. Заголовок, дані й ширина блоку спільні. Після застосування до чернетки натисніть «Зберегти сторінку».

Старі діаграми використовують ECharts зі своїми поточними параметрами. Новий профіль іншої бібліотеки починається з поточних параметрів; наступні перемикання відновлюють збережений профіль. JSON-резервні копії й обидва ZIP-варіанти публікації зберігають усі профілі. CSV/XLSX змінюють дані, зберігаючи поточні налаштування блоку.

Бібліотеки й ліцензії зберігаються локально в `src/vendor/`; CDN не потрібен. Plotly використовує офіційну базову збірку (bar, scatter, pie), яка підтримує всі наявні типи діаграм. Файли бібліотеки завантажуються лише коли вона використовується на відкритій сторінці; автономний HTML містить усі три бібліотеки. `npm run vendor` відновлює файли з зафіксованих npm-залежностей. Якщо завантаження бібліотеки не вдалося, показується резервна діаграма з повідомленням.


Панель фільтрів грантових проєктів адаптується до ширини самого блоку: на широкому блоці всі елементи стоять в один рядок, на середньому кнопки програм займають окремий другий рядок, на вузькому пошук розташований над списками «Програма» та «Роль ЗВО», а кількість результатів і скидання — під ними. Вибрана програма синхронізується між кнопками та списком при зміні ширини. «Скинути фільтри» видно лише за наявності активних умов; скидання повертає фокус у пошук. Така сама панель працює у візуальному редакторі та в обох варіантах публікації.


Тип **Горизонтальні накопичувальні стовпчики** складає значення серій уздовж горизонтальної осі. Налаштування **Показувати значення справа від стовпчиків** керує сумою активних серій наприкінці кожного стовпчика. Доступні перенесення довгих назв, підписи сегментів, легенда, палітри, підказки та період. Тип підтримують усі три бібліотеки; вибір переноситься через резервні копії та публікацію.


Після лічильника результатів каталогу грантових проєктів є перемикач вигляду з двох іконок. Підказки **Картки / Таблиця** показуються при наведенні; кнопки також мають доступні назви для клавіатури та екранних читачів. Початковий вигляд — картки. Таблиця містить назву й посилання, програму та її позначення, роль ЗВО, період, надходження і часовий прогрес. Обидва вигляди використовують той самий пошук і фільтри; скидання фільтрів зберігає вибраний вигляд. Під час перегляду режим зберігається при переході між роками й сторінками та вибирається окремо для кожного блоку. Таблиця підлаштовується під ширину блоку без горизонтальної прокрутки; на вузькому екрані рядки переходять у компактний вигляд із підписами полів. Перемикач доступний відвідувачам, у візуальному редакторі та в обох варіантах публікації.


Часовий прогрес проєктів у картках і таблиці округлюється до найближчих 5% (наприклад, 97% → 95%, 61% → 60%, 24% → 25%). Число, смуга, підказка й доступне значення використовують один розрахунок.


Горизонтальні діаграми використовують спільну область назв для всіх трьох бібліотек. Підписи вирівняні ліворуч із відступом 8 px, а перенесення враховує фактичну ширину тексту вибраного шрифту. Короткі сполучники та прийменники залишаються з наступним словом, коли ця пара вміщується в рядок. При однаковій ширині блоку підписи однаково відображаються в адмінці та на сторінці відвідувачів.


У каталозі публікацій стовпець **Квартиль** показує Q1, Q2, Q3, Q4 або **Без квартиля**. Порожня комірка та явне «Без квартиля» при імпорті CSV/XLSX/JSON трактуються однаково; ці записи знаходить фільтр «Без квартиля». Для розрахунків відсутній квартиль зберігається як `null`, а в каталозі та редакторі блоку показується текстовий підпис. Інші значення (наприклад Q5) відхиляються під час перевірки імпорту.


### Фактичні надходження грантів і звітні роки

**Адмінка → Надходження грантів за роками** відкриває редактор: оберіть проєкт, введіть фактичні суми у тис. грн за роками та, за потреби, фактичне виконання з кроком 5%. Можна перемикатися між проєктами без втрати чернеток і зберегти всі зміни однією кнопкою. Порожня сума означає відсутність даних, явний нуль — підтверджений нуль. Загальний бюджет не ділиться на роки автоматично.

Для синхронного оновлення карток і «Кошти за програмами» оберіть у налаштуваннях блоків джерело **Аналітика сайта**. Власні дані окремого блоку залишаються окремими. У звіті за рік картка показує тільки запис `funding` за цей рік, а програма — суму таких записів усіх її проєктів. За весь період підсумовуються лише роки до поточного включно. Дати завершення проєктів можуть залишатися майбутніми.

Приклад проєкту 2024–2028: `funding: [{"year":2024,"amountThousandUAH":250},{"year":2025,"amountThousandUAH":900},{"year":2026,"amountThousandUAH":120}]`. У 2026 році картка покаже 120 тис. грн, а не третину загальної суми. Необов’язкове `progressByYear: [{"year":2026,"percent":65}]` задає фактичне виконання; якщо запису немає, використовується розрахунок за датами станом на кінець минулого звітного року або сьогодні для поточного.

`progressByYear` переноситься у JSON та як JSON-комірка CSV/XLSX; старі файли без цієї колонки підтримуються. Спільний набір, річні суми й виконання входять до резервних копій та обох ZIP-варіантів публікації. Початкові майбутні записи не видаляються під час редагування історичних років, але не включаються в поточні звіти.

Перелік **Звітний період** обмежений поточним календарним роком за часом Києва: у 2026 році 2027 і 2028 приховані. З початком 2027 року 2027 додається автоматично, також у відкритій вкладці.


### Каталог публікацій: джерело даних і вигляд

У **Налаштуваннях** блоку «Каталог публікацій» джерело визначає записи:

- **Аналітика сайта — автоматичний розрахунок** читає спільний набір публікацій за вибраний звітний рік. Імпорт через «Керування даними» оновлює також пов’язані графіки та показники.
- **Власні дані цього блоку** — окрема копія таблиці за період на момент редагування. «Редагувати» та імпорт CSV/XLSX у блок створюють цю копію; вони не змінюють вихідні записи інших блоків. Повернення на «Аналітика сайта» знову показує спільний набір замість ручної копії.

Обидва режими мають однаковий оформлений каталог із пошуком за назвою/авторами, фільтрами факультету, індексації та квартиля, а також поділом на сторінки. Вісім колонок у редакторі — поля запису, а не вісім видимих стовпців: автори та тип розташовані під назвою, факультет має свій стовпець, індексація й квартиль — мітки. Рік і адреса залишаються в даних. Зберігайте назви колонок для розпізнавання полів; їхній порядок можна змінювати.

**Посилання зробити активним для назви статті** — увімкнено за замовчуванням. Заповніть поле «Посилання» повною http/https-адресою: назва відкриватиме статтю в новій вкладці. Порожня адреса або вимкнений пункт залишають назву звичайним текстом; окремий стовпець посилань не додається. Ця опція працює для обох джерел і зберігається в резервній копії та ZIP-публікації.

**Показувати весь список (без прокрутки)** вимикає вертикальну прокрутку й поділ на сторінки. Ширина блоку визначає доступне місце; шрифти й кольори налаштовуються через стилі та тему сайта. Після зміни блоку натисніть **Застосувати до чернетки**, потім **Зберегти сторінку**. Локальні редагування стають спільними після експорту сайта для публікації й заміни файлів на хостингу.


### Грошові одиниці — тис. грн

Усі фінансові показники, картки й таблиці проєктів, діаграми, річний редактор, імпорт та експорт використовують **тис. грн**. Приклади: 1,13 млн ₴ = **1 130 тис. грн**; 2 280 000 грн = **2 280 тис. грн**. Дані за роками підсумовуються в цих самих одиницях. Нуль та відсутність даних залишаються різними значеннями.

Поточний JSON має `schemaVersion: 2`; суми зберігаються в явному полі `amountThousandUAH`. Це поле також використовується в CSV/XLSX надходжень та в записах `funding` проєктів. Наприклад: `{"year":2026,"amountThousandUAH":1130}`. Дозволено до п’яти знаків після коми у тисячах для збереження точності до копійки; округлення при перенесенні не виконується.

Старі набори JSON версії 1 і CSV/XLSX з полем `amountUAH` у гривнях підтримуються: сума ділиться на 1000, а наступний експорт уже містить `amountThousandUAH`. Одночасно вказувати обидва поля одного запису не можна.

Збережені власні дані блоків і старі резервні копії теж переводяться: числові значення в колонках/картках із «млн ₴» чи «млн грн» множаться на 1000; гривні та стара річна таблиця «Надходження за джерелами» діляться на 1000. Заголовки змінюються на «тис. грн». Ознака `moneyUnit: "thousandUAH"` і явні одиниці в заголовках запобігають повторному перерахунку. Роки, кількості записів, відсотки, посилання й оформлення зберігаються. Оновлені одиниці й значення входять до обох ZIP-версій публікації.


### Розміри діаграм в адмінці та округлення відсотків

ECharts отримує виміряну ширину та висоту полотна явно, зокрема у візуальному перегляді адмінки. Розмір графіка узгоджується з шириною блоку після перемикання сторінки, зміни ширини та повторного відкриття редактора; висота прогрес-діаграми враховує кількість рядків.

Для кругової та кільцевої діаграм у **Налаштування → Відображення значень і підсумків** увімкніть **Відображати числові значення всередині сегментів у відсотках**. Нижче доступний вибір **Округлення відсотків**: **До десятих (12,3%)** або **До цілих (12%)**. За замовчуванням — до десятих.

Для округлення до цілих додатково доступний пункт **Якщо відсоток менше 1%, показувати з округленням до десятих**. Він зберігає, наприклад, 0,4% замість 0%; якщо його вимкнути, 0,4% округлюється до 0%. Числові значення самих даних не змінюються. Частки враховують суму видимих секторів, тому після приховування категорій через легенду перераховуються. Опції працюють у всіх трьох бібліотеках і резервних SVG-діаграмах, зберігаються окремо для кожної бібліотеки та входять у резервні копії й ZIP-публікацію. Після зміни натисніть **Застосувати до чернетки → Зберегти сторінку**.


### Повні списки та рамка активного поля

Нові блоки мають увімкнений пункт **Показувати весь список (без прокрутки)**. Для наявних аналітичних блоків **Картки основних показників, Грантові проєкти, Каталог публікацій, Внесок факультетів, Реєстр патентів, Надходження за джерелами** цей пункт також вмикається один раз при відкритті оновленого сайта або імпорті старої копії. Дані, кольори та ширина блоків зберігаються. Подальше ручне вимкнення зберігається завдяки ознаці `listDisplayVersion: 1` і повторно не скидається. У каталогах повний список також вимикає поділ на сторінки.

**Налаштування → Стилі → Виділення активних полів і фільтрів** містить спільний перемикач **Підсвічувати рамку активного поля** та вибір кольору. За замовчуванням виділення вимкнене. Увімкнена рамка малюється всередині поля, тому її не обрізають краї контейнерів. Для пошуку рамка охоплює все поле з іконкою. Параметр `institution.styles.focusHighlight` зберігає `enabled` і `color` для всього сайта, незалежно від пресета шрифтів. Колір застосовується до сторінок, адмінки, локального перегляду та обох ZIP-версій, переноситься через JSON/XLSX та резервну копію. Закриття налаштувань без збереження скасовує попередній перегляд.


### Тексти та видимість унизу бічного меню

У **Налаштування → Університет → Тексти бічного меню** можна редагувати повідомлення про відкриті дані й слоган та окремо приховувати повідомлення, слоган, повну назву закладу та підзаголовок. Для назви й підзаголовка використовуються наявні поля `institution.name` і `institution.subtitle`; адреса назви береться з `institution.website`. Вимкнення прапорця зберігає текст для повторного ввімкнення. Порожні повідомлення, слоган і підзаголовок не показуються; приховані секції не залишають порожніх контейнерів. Перенесення рядків у слогані зберігаються.

Повний XLSX містить додаткові окремі рядки на аркуші **Університет**:

| Ключ | Значення |
| --- | --- |
| `institution.sidebarStatus` | Текст повідомлення про відкриті дані |
| `institution.sidebarTagline` | Текст слогана; можна вводити кілька рядків |
| `institution.showSidebarStatus` | true / false — показувати повідомлення й зелену позначку |
| `institution.showSidebarTagline` | true / false — показувати слоган |
| `institution.showSidebarName` | true / false — показувати назву закладу з посиланням |
| `institution.showSidebarSubtitle` | true / false — показувати підзаголовок |

У Excel прапорці експортуються як логічні значення (TRUE/FALSE, ІСТИНА/ХИБНІСТЬ залежно від мови Excel). Старі книги без цих шести рядків підтримуються: застосовуються початкові тексти; повідомлення, слоган та підзаголовок типово приховані, назва закладу відображається. Параметри також входять у JSON, резервну копію сайта та обидва ZIP-варіанти публікації. Частковий CSV/XLSX імпорт таблиць не скидає ці налаштування. Вигляд бічного меню однаковий у локальному перегляді й опублікованій версії.


### Початковий вигляд діаграм публікацій і коштів за програмами

**Публікації за роками** та **Якість публікацій** типово показують легенду **внизу, по центру**. Для квартилів також увімкнені підписи сегментів у відсотках із округленням **до десятих**.

**Кошти за програмами** типово використовує **Горизонтальну стовпчасту діаграму** й підзаголовок **Надходження коштів, тис. грн**. Власний підзаголовок або явне порожнє значення зберігаються.

Початкові параметри старих аналітичних блоків оновлюються один раз, разом із збереженими профілями бібліотек: верхня легенда публікацій переноситься вниз і центрується; початкові стекові стовпчики програм стають горизонтальними; для квартилів вмикаються відсотки. Дані, кольори й ширина залишаються збереженими, власні типи графіків та праві/приховані легенди не скидаються. Ознака `chartDefaultsVersion: 1` дозволяє після оновлення змінювати ці параметри вручну без повторного скидання. Нові блоки відразу використовують актуальні типові параметри.

### Публікації в Scopus за типом документів

На сторінці «Публікації» збережено типову накопичувальну стовпчасту діаграму «Публікації в Scopus за типом документів» із таблицею з наданого `Type.xlsx`: 2021–2026 роки, Conference paper, Article, Book chapter, Book та Other publications. Діаграма показує всі роки, має ширину 66% і легенду внизу по центру. Наступний блок «Внесок факультетів» має ширину 34%, тому на широкому екрані вони стоять поруч; каталог публікацій розміщено після цієї пари. Таблиця й налаштування доступні для редагування та експорту/імпорту блока.

Серверні типові дані лежать у `data/pages.json`. При відкритті раніше збереженого сайта новий блок додається один раз, а наявний блок факультетів переміщується поруч зі збереженням його даних і оформлення. Прапорець сторінки `scopusLayoutVersion: 1` зберігає подальші ручні зміни, включно з видаленням діаграми. Інші блоки не перезаписуються. Якщо сторінка вже містить 50 блоків, автоматичне додавання відкладається до звільнення місця.

### Автоматична кількість карток показників у рядку

У налаштуваннях блоків показників додано перемикач **«Без обмеження кількості карток по ширині»** (`settings.autoColumns`). Він вимикає поле фіксованої кількості: сітка автоматично заповнює доступну ширину картками, переносить їх на наступний рядок і може показувати понад шість карток у широкому блоці. На вузькому екрані картки перебудовуються без горизонтальної прокрутки. Це працює для власних карток, автоматичних показників і ручних копій аналітики.

Перемикач типово увімкнений для нових блоків. Старі блоки показників переходять на автоматичне розташування один раз; ознака `metricLayoutVersion: 1` зберігає подальше ручне вимкнення. Попереднє значення «Кількість карток по ширині» зберігається й застосовується знову після вимкнення автоматичного розташування. Налаштування входить до JSON блока, резервної копії та обох ZIP-варіантів сайта; CSV/XLSX-імпорт даних наявного блока його не скидає.

### Інформаційна картка «Відкрита наука»

У палітрі **Адмінка → Додати блок → Інформаційна картка** доступний окремий тип `feature` зі зразком «Відкрита наука» (початкова ширина 34%). Це незалежний інформаційний блок: його вміст не змінюється при перемиканні року чи імпорті аналітичних записів.

Олівець відкриває окремі поля: напис біля іконки, заголовок картки, опис, текст і адреса посилання, дві іконки та відкриття в новій вкладці. Порожній текст приховує відповідний елемент; порожня адреса приховує посилання. Переноси рядків у заголовку й описі зберігаються. У параметрах блока також доступні зовнішній заголовок, підзаголовок, ширина й оформлення картки: фон теми або власний колір, кольори всіх текстів і рамки, вирівнювання, мінімальна висота, відступи, заокруглення, товщина рамки та розміри чотирьох текстових елементів. При збільшенні вмісту картка росте за висотою.

Наявні аналітичні блоки `insight` автоматично переходять у цей шаблон зі збереженням ID, заголовка, видимості та ширини. Для старих ручних блоків зберігається їхній текст; початкові опис і посилання не додаються поверх ручного вмісту. Нові зміни зберігаються в поточному браузері після **Застосувати до чернетки → Зберегти сторінку**.

JSON блока, резервна копія сайта й обидва ZIP-варіанти містять весь вміст та оформлення. CSV/XLSX передають дев’ять колонок вмісту (`title`, `eyebrow`, `headline`, `text`, `linkLabel`, `linkUrl`, `icon`, `linkIcon`, `openInNewTab`) одним рядком; при імпорті в наявну картку її оформлення зберігається. `openInNewTab` у таблиці — `true` або `false`. Зовнішні адреси допускають http/https, внутрішні — `#publications` чи `#page/slug`; HTML у тексті відображається як звичайний текст.

В оформленні інформаційної картки доступний чекбокс **«Висота по тексту»** (`appearance.autoHeight`, типово вимкнений). Він прибирає мінімальну висоту картки та розтягування зовнішнього блока до висоти сусідів: висота визначається вмістом, відступами й рамкою. Поле мінімальної висоти стає неактивним, але його значення зберігається й повертається після вимкнення чекбокса. Вибір переноситься через JSON, резервну копію та обидва ZIP-варіанти сайта; імпорт CSV/XLSX у наявний блок його зберігає.

### Типовий вигляд діаграм грантових проєктів

«Проєкти за роками» та «Кошти за програмами» типово приховують легенди. Початкові підзаголовки — відповідно «Кількість проєктів за роками» та «Надходження коштів, тис. грн». Наявні блоки оновлюються один раз, разом із профілями усіх бібліотек діаграм; дані, кольори, тип діаграми, ширина та власні підзаголовки зберігаються. Ознака `grantChartDefaultsVersion: 1` дозволяє надалі змінювати легенду вручну без повторного скидання. Налаштування переносяться через JSON, резервну копію й обидва ZIP-варіанти сайта.

Пресет **«Компактний 1»** відтворює надані скріни: основний текст 14 px, заголовок сторінки 32 px, заголовки блоків 18 px, числа показників 30 px, меню 14 px, елементи керування 14 px, таблиці 13 px, підписи діаграм 13 px, примітки 13 px; міжрядковий інтервал 1,1; відступи між абзацами 6 px, між блоками 12 px, усередині блоків 14 px, вертикальні відступи клітинок 6 px, заокруглення 10 px. Підсвічування рамки активного поля вимкнено. Конфігурацію збережено в обох початкових наборах даних і функції початкових стилів.

### Ширина блока: відсотки, пікселі та автоматичне заповнення

У вікнах **Ширина блоку** й **Налаштування → Ширина блоку** є три режими: «У відсотках», «Фіксована ширина, px» та «Підібрати автоматично». Для прикладу з двома блоками виберіть правому фіксовану ширину 250 px, а лівому — автоматичну. Лівий заповнить решту рядка з урахуванням проміжку. Підтримується власна ціла ширина від 80 до 4000 px. Кнопка над блоком показує поточну ширину: %, px або «Авто».

Сусідні блоки з фіксованою й автоматичною шириною утворюють окрему групу рядків. Кілька автоматичних блоків ділять вільну ширину порівну. Якщо місця недостатньо, блоки переносяться; на телефоні вони займають повну ширину й розміщуються один під одним. Блоки у відсотках задають межі цих груп та продовжують використовувати звичне розташування.

Режим зберігається в `settings.widthMode` (`percent`, `fixed`, `auto`), ширина в пікселях — у `settings.widthPixels`; попередній відсоток `settings.width` зберігається для повернення до нього. Початковий режим наявних і нових блоків — відсотки, початкове значення поля пікселів — 250. Параметри спільні для всіх бібліотек діаграми й переносяться через JSON блока, резервну копію та обидва ZIP-варіанти. Імпорт CSV/XLSX даних наявного блока не скидає його ширину. Після застосування до чернетки збережіть сторінку.

### Повні назви діаграм на мобільному екрані

Лінійчаті діаграми прогресу, зокрема «Внесок факультетів», показують повні назви над смугами з перенесенням рядків. Висота діаграми розраховується з урахуванням найдовшого підпису, нумерації та значень. Це спільне відображення для ECharts, Chart.js і Plotly; при зміні ширини екрана розмітка перераховується. Підписи горизонтальних стовпчастих діаграм на телефоні також переносяться автоматично.

Спливні підказки обмежені шириною діаграми й екрана: HTML-підказки ECharts переносять текст, а для Chart.js і Plotly рядки розраховуються за шириною шрифту. Повні назви, числові значення та підсумки зберігаються. Зміна працює в редакторі, локальному HTML та обох ZIP-варіантах публікації без зміни даних або збережених налаштувань блоків.

### Візуальний вибір фону карток показників

Відкрийте **Редагувати** в блоці показників і натисніть поточний фон у колонці **«Фон картки»**. Відкриється палітра з такими самими кольоровими зразками й перемикачами, як у фону текстового блока: колір меню, основний акцент, блакитний, зелений, теплий і фіолетовий відтінки, стандартний фон та власний колір. Обраний варіант виділено рамкою. Вибір власного кольору автоматично вмикає відповідний варіант; скасування або Escape залишає попередній фон картки.

Натисніть **Застосувати** в палітрі, потім **Застосувати до чернетки** в редакторі та **Зберегти сторінку**. Кожна картка має незалежний фон. Зміна тільки фону зберігає автоматичні числа, іконки, порівняння та оновлення за роком; фони переносяться через наявні JSON/CSV/XLSX і ZIP-функції. Кольори теми змінюються разом із темою сайта, власний колір зберігається, контрастний колір тексту підбирається автоматично.

### Початкові кольори основних показників

Для «Картки основних показників» початкові фони відповідають наданому зразку: наукові публікації — блакитний, Scopus / Web of Science — теплий, публікації Q1–Q2 — фіолетовий, грантові проєкти — зелений, надходження грантів — блакитний, патенти — теплий. Кольори прив’язані до назв показників і змінюються разом із темою сайта; вони зберігають автоматичні числа, іконки, порівняння й оновлення за роками.

Набір застосовується до нових блоків та наявних автоматичних основних показників без власного `metricAppearance`. Збережене власне оформлення, у тому числі явно обраний стандартний фон, не перезаписується. Кольори видно одразу при додаванні блока, у редакторі палітри та в обох ZIP-варіантах. JSON і резервна копія передають `metricAppearance`; CSV/XLSX даних блока містять кольори в колонках `background` і `backgroundColor`.

### Примітка з даними

Початкова «Примітка про фінансування» підсумовувала `revenues[].amountThousandUAH` за вибраний рік: порожній набір означає «дані не завантажено», а запис із нулем — нульове надходження. Грантові кошти з проєктів до цієї суми автоматично не додаються. Тепер такі блоки переходять в окремий тип **«Примітка з даними»**, доступний у палітрі **Додати блок**. ID, зовнішній заголовок, видимість і ширина зберігаються. Ручний текст старої примітки теж зберігається; він не замінюється автоматичним розрахунком.

У налаштуваннях та редакторі примітки можна вибрати:

- **Джерело**: таблиця аналітики сайта, конкретний блок таблиці/діаграми на будь-якій сторінці або власне значення/текст.
- **Режим періоду**: оновлювати за роком сторінки або завжди показувати фіксований рік чи діапазон (наприклад, 2021–2025). Фіксований період не залежить від перемикання року.
- **Розрахунок**: сума, середнє, мінімум, максимум, кількість рядків, кількість різних назв або значення одного рядка. Можна вибрати конкретну колонку, усі числові колонки та фільтр за назвою з першої колонки. Окреме значення може бути текстовим. Для карток із різними одиницями виміру слід вибрати конкретний показник.
- **Вигляд**: вступ, текст, повідомлення за відсутності даних, іконка, одиниця та точність числа. Палітра фону така сама, як у текстових блоків: кольори теми та власний колір із автоматичним контрастом тексту. Також доступні всі режими ширини блока.

У тексті й вступі доступні підстановки `{value}`, `{unit}`, `{source}`, `{period}` (2026 або 2021–2025) і `{periodLabel}` («у 2026 році» або «за 2021–2025 роки»). Попередній перегляд показує результат під час редагування. Дані беруться з таблиці джерела, а не з видимих стовпчиків чи прихованих легенд діаграми; джерело не змінюється.

Для власних таблиць підтримуються колонка «Рік»/`year`, дата «Дата»/`date`, роки у першій колонці або окремі колонки 2024, 2025 тощо. Без такого поля статична таблиця дає однакові значення при перемиканні року. У фіксованому періоді таблиця без року враховується один раз. Порожні клітинки та «—» пропускаються; справжній нуль зберігається. Якщо джерело або колонку видалено, блок показує зрозуміле повідомлення для перепідключення.

JSON, резервна копія та обидва ZIP-варіанти зберігають прив’язку, період і оформлення. CSV/XLSX примітки переносять її заголовок, вступ, текст, повідомлення за відсутності даних та іконку; прив’язка й фон наявного блока при такому імпорті зберігаються. Підключене приховане джерело зберігається в ZIP для відвідувачів як прихований блок, щоб примітка продовжувала оновлюватись за роками. Після застосування параметрів збережіть сторінку. Для оновлення сайта для всіх опублікуйте новий ZIP.

### Надзаголовок сторінки

В **Адмінка → потрібна сторінка → Параметри сторінки** поле **Надзаголовок** змінює напис над основним заголовком. Порожнє поле приховує напис і крапку. Зміни одразу видно в попередньому перегляді; після редагування натисніть **Зберегти сторінку**. Значення окреме для кожної сторінки та переноситься через JSON і обидва ZIP-варіанти. Старі сторінки без цього поля зберігають напис «НАУКОВА ДІЯЛЬНІСТЬ».

### Логотип і прокрутка меню

У **Налаштування → Університет → Логотип і верхня частина меню** можна завантажити PNG/SVG/WebP/JPEG до 2 МБ, повернути білий логотип КАІ або вибрати стандартну іконку з короткою назвою закладу. Поле **Текст під логотипом** підтримує переноси рядків; порожнє значення приховує підпис. Попередній перегляд змінюється під час редагування, а кнопка **Зберегти налаштування** застосовує зміни до сайта.

Прапорець **Дозволити окрему прокрутку меню** керує власною смугою прокрутки. Якщо вимкнути, меню прокручується разом зі сторінкою; на телефоні відкритий список також рухається разом зі сторінкою, щоб нижні пункти залишались доступними. За замовчуванням окрема прокрутка ввімкнена. У цьому режимі смуга прокрутки відображається постійно; прокручувати меню можна, коли його вміст перевищує висоту екрана. Перемикач застосовується після збереження налаштувань.

Логотип зберігається всередині налаштувань, без зовнішніх посилань. Завантажені зображення оптимізуються, зберігають прозорість і переносяться разом із підписом та режимом прокрутки через JSON, повну XLSX-книгу та обидва ZIP-варіанти сайта. Старі дані отримують білий логотип КАІ, підпис SCIENCE & INSIGHTS і поточний режим прокрутки; збережені явні значення не замінюються.
